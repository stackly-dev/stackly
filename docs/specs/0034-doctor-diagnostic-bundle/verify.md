## Milestone 1: Doctor contract and daemon checks

_Kelima langkah milestone ini ada di bawah: langkah 1 (kontrak `doctor.run`, protokol 3.4), langkah 2 (`ListenerLookup`), langkah 3 (`Registry::quick_check`, `scan_unrecognized`), langkah 4 (`stackly-core::doctor`), dan langkah 5 (`stacklyd::ipc::doctor` dan `apps/daemon/tests/doctor.rs`)._

_Catatan langkah 3 (disetujui lead 2026-11-10): `CODED_COLUMNS` dan pindai ada di `crates/storage/src/registry/coded.rs`, `quick_check` di `health.rs`; mapper baris di `stackly-storage` tidak membaca kolom berkode lewat entri `CODED_COLUMNS`. Kelengkapan daftar dijaga test: setiap kolom schema dengan CHECK `code` harus ada di `CODED_COLUMNS` atau di `FREE_CODE_COLUMNS` beserta alasannya, dan kode asing di setiap entri membuat baca biasa gagal `Corrupt`. Test AC-8 memakai kolom set terbuka; `lifecycle` adalah set tertutup dan tertangkap `quick_check`._

_Catatan langkah 1, 4, dan 5 (tafsiran `dev-f34-m1`, belum disetujui lead): (a) `DoctorFindingCode` mendapat `daemon_unreachable` (check `connection`, detail `code` memuat kode `ipc.*`) dan `agent_state` (check `background_agent`, detail `state` memuat state spec 0015), karena tabel *Daftar check* menulis keduanya sebagai kode error dan state, bukan kode temuan, dan milestone 4 hanya menyentuh `apps/cli`; (b) `cli.doctor_found_errors` masuk katalog di langkah 1 dengan konstruktor `CliFailure::doctor_found_errors` bertanda `provisional`, karena katalog CLI ada di `stackly-protocol`; (c) usia folder scratch diambil dari waktu di dalam nama UUID versi 7, karena port `Filesystem` tidak membaca waktu ubah; nama yang bukan UUID v7 tidak pernah dibuat Stackly, jadi selalu dilaporkan; (d) baris PID dan lock di *Hasil check processes* hanya dibaca untuk instance yang lifecycle nya menyatakan proses hidup (`starting`, `running`, `recovering`, `stopping`, `unknown`) atau yang punya blocker identitas, karena observasi tetap ada di registry setelah stop biasa; (e) `inspect` yang ditolak (`PermissionDenied`) dihitung PID hidup milik user lain, jadi `pid_reused` dengan `sameUser` false; (f) run ketiga menunggu slot paling lama 15 detik lalu berjalan tanpa slot; (g) semua check berjalan bersamaan, jadi batas 5 detik per check adalah tenggat bersama run itu; (h) dalam recovery mode `instanceId` tidak dibaca (registry tidak disentuh) dan `scope` null; (i) `Doctor` daemon disimpan per `serverInstanceId` di `ipc::doctor` (`provisional`) sampai lead mengizinkan field di `DaemonCore`._
